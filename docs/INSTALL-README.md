# سعي بلس — حماية جواز المهارات (النسخة المحدثة)

## ما الذي تعالجه هذه الحزمة؟

1. بيانات الجواز لا تُقرأ أو تُحفظ في `localStorage` أو `sessionStorage`. يتم تحميلها وحفظها عبر `/api/skill-passport` في قاعدة Cloudflare D1.
2. يحدد الخادم مالك السجل من `getChatGPTUser()` فقط؛ لا يقبل `userId` أو `ownerId` من جسم الطلب أو عنوان URL. كل استعلام قراءة/تعديل/حذف مربوط بمعرّف الهوية الذي أعادته خدمة الاستضافة الموثوقة.
3. أصبح مسار API **مغلقًا افتراضيًا** ما لم يُضبط متغير بيئة الخادم `SAEE_AUTH_HEADERS_TRUSTED=true`. هذا إقرار تشغيلي بأن بيئة الاستضافة نفسها تتحقق من الهوية وتزيل/تستبدل أي ترويسات `oai-authenticated-*` يرسلها العميل.
4. يتم التحقق من مصدر طلبات الكتابة، ونوع المحتوى، وحجم جسم الطلب (256 KiB)، وبنية كل حقل، والروابط، والقيم المسموح بها. `If-Match` يمنع الكتابة فوق نسخة أحدث من نافذة أخرى.
5. تُرسل استجابات الجواز مع `Cache-Control: private, no-store`; ولا يوجد رابط عام حقيقي، ويبقى خيار النشر العام معطلًا.
6. عند فشل الحفظ، تتوقف التعديلات الجديدة وتبقى المسودة في ذاكرة الصفحة لفترة مؤقتة، مع زر لتنزيل نسخة إنقاذ وزر لإعادة المحاولة في الأخطاء المؤقتة. يُحذّر المتصفح قبل مغادرة الصفحة مع وجود تعديلات غير مؤكدة. إذا أعاد الخادم `401`، تُمسح بيانات الصفحة فورًا حمايةً لمستخدم سابق على جهاز مشترك؛ لذلك لن تحتفظ الواجهة بمسودة بعد انتهاء/رفض الجلسة.
7. تُمسح واجهة المعاينة من DOM والذاكرة عند إخفاء الصفحة/الانتقال عنها، ولا تُحمّل بيانات أي حساب إلا بعد نجاح طلب API للمستخدم المسجل.

## الملفات

- `public/skill-passport.html` — الواجهة ورسائل الدخول والحفظ/الاستعادة.
- `public/skill-passport.js` — تحميل وحفظ خادميان، وعدم وجود تخزين محلي احتياطي، حماية من فقد التعديلات وتنظيف حالة الصفحة.
- `public/skill-passport.css` — تنسيق عناصر الحفظ والاستعادة.
- `app/api/skill-passport/route.ts` — واجهة API للمستخدم الحالي: GET/PUT/DELETE.
- `lib/skill-passport-validation.mjs` — تحقق وتطبيع خادمي صارم.
- `db/schema.ts` — جدول `skill_passports` مع الإبقاء على `site_content`.
- `drizzle/0001_skill_passports.sql` و`drizzle/meta/` — هجرة D1.
- `tests/skill-passport-security.test.mjs` — اختبارات قواعد التحقق وحدود API.
- `tests/skill-passport-client.test.mjs` — اختبارات حفظ الواجهة والتعافي.
- `tests/test_skill_passport_migration.py` — اختبارات هجرة SQLite وعزل المستخدمين ونسخ الحفظ.
- `.github/workflows/skill-passport-tests.yml` — اختبارات تلقائية عند push/PR.

## إعداد الهوية — لا تتخطَ هذه الخطوة

يُقرأ المستخدم عبر helper المشروع `app/chatgpt-auth.ts`. هذا helper يعتمد على ترويسات هوية تضيفها منصة ChatGPT Sites. قبل تمكين API:

1. انشر التطبيق في **ChatGPT Sites/بيئة الاستضافة الموثوقة للمشروع**، حيث تتحقق المنصة من تسجيل الدخول وتضع ترويسات الهوية على جهة الخادم.
2. تأكد أن أي طلب مباشر من الإنترنت لا يستطيع تمرير قيم يختارها بنفسه لترويسات `oai-authenticated-user-id`, `oai-authenticated-user-email` و`oai-authenticated-user-full-name`. إذا كانت البيئة لا تضمن ذلك، **لا تضبط المتغير التالي** ولا تعرض الـ API على عامل Cloudflare عام مستقل.
3. من إعدادات متغيرات البيئة الخادمية للموقع (لا في ملفات الواجهة أو Git) أضف `SAEE_AUTH_HEADERS_TRUSTED` بقيمة `true` بعد التحقق من النقطة السابقة. عند تركه دون ضبط يرجع API خطأ 503 عمدًا، فلا يعمل الحفظ.
4. تأكد من وجود Binding باسم `DB` إلى قاعدة D1 الصحيحة. لا تضع أي مفاتيح أو أسرار في `public/`.

> المتغير `SAEE_AUTH_HEADERS_TRUSTED` ليس إثبات هوية بحد ذاته ولا بديلًا عن التحقق من هوية المنصة؛ هو قفل تشغيلي يمنع تفعيل API عرضًا. لا تُفعّله في نشر يستقبل الترويسات غير الموثوقة مباشرةً.

## تطبيق هجرة D1

نفّذ `drizzle/0001_skill_passports.sql` مرة واحدة على قاعدة D1 الصحيحة. إذا كنت تستخدم Wrangler مع معرّف قاعدة الإنتاج الفعلي:

```bash
pnpm exec wrangler d1 execute <REAL_D1_DATABASE_NAME_OR_ID> --remote --file=drizzle/0001_skill_passports.sql
```

لا تستخدم اسمًا تخمينيًا لقاعدة البيانات. راجع Cloudflare واختر الـ binding `DB` نفسه الذي يستخدمه التطبيق. هذه الهجرة تضيف جدولًا جديدًا ولا تحذف جدول `site_content`.

## الاختبار

من جذر المشروع شغّل الأوامر التالية (لا تحتاج تثبيت dependencies لاختبارات هذه الحزمة):

```bash
node --check public/skill-passport.js
node --check lib/skill-passport-validation.mjs
node tests/skill-passport-security.test.mjs
node tests/skill-passport-client.test.mjs
python3 tests/test_skill_passport_migration.py
```

سير عمل GitHub `skill-passport-tests.yml` يشغّل نفس الاختبارات على push وpull request.

## قبل الإنتاج

1. لا يعتبر حل الهوية جاهزًا حتى تُؤكَّد موثوقية ترويسات الهوية من المنصة المضيفة ولا يكون هناك أصل بديل مكشوف يتجاوزها.
2. اختبر مستخدمين منفصلين: أنشئ جوازًا للحساب A، ثم جرّب GET/PUT/DELETE للحساب B، وتأكد أن B لا يقرأ أو يعدّل سجل A.
3. اختبر انتهاء الجلسة، و503، و409، وإعادة المحاولة، وتنزيل نسخة الإنقاذ، ثم شغّل `pnpm lint` و`pnpm build` للمشروع الكامل.
4. النسخة الثابتة على GitHub Pages لا تشغّل `app/api/skill-passport/route.ts` ولا توفر D1. لا تعتبر النشر على Pages دليلًا على عمل الحفظ الخادمي.
5. احفظ نسخة محلية من بيانات جواز قديمة قبل استبدال الواجهة؛ لن تُنقل بيانات `localStorage` القديمة تلقائيًا إلى حساب جديد منعًا لخلط بيانات المستخدمين.
